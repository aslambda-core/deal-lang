# DEAL — компилятор и виртуальная машина (пилот v0.2.0)

DEAL — язык договоров: программа хранится как канон-AST (JSON), читаемый вид
(проекция) печатается из AST, а исполнение судится свидетель-кейсами —
вход → выход / канонический отказ.

## Что в пакете

- `deal/` — компилятор и ВМ на Python (стандартная библиотека, без зависимостей):
  - `ast.py` — канон-AST: загрузка, детерминированная сериализация, серийный хеш, проекция;
  - `kompilyator.py` — 8 стадий сделки; отказ всегда словами: {стадия, виновник, причина, что_править};
  - `vm.py` — исполнение сделки против свидетелей; примитивник — замороженный набор операций;
  - `proekciya.py` — печать AST ↔ разбор проекции (биективно);
  - `bajtkod.py` — канон-AST → плоский стековый код;
  - `kodogen.py` — тело, доказанное статсудом, компилируется в настоящую Python-функцию;
  - `s2_format.py` — текстовый формат скомпилированной программы (вход для C-семени);
  - `kesh.py` — кеш вердиктов свидетелей (v0.2.0): только сделки без полки в
    транзитивном замыкании зова; ключ несёт хеш ВМ — смена семантики
    инвалидирует сама; запись атомарная.
- `komponenty/` — восемь зелёных компонентов `.deal`: арифметика с копейками,
  факториал (скрытые края + требует-ограждение), счётчик на полке, оракул над
  компонентом, сверка полок, TF-IDF-поиск, оракул времени.
- `polka/` — фиксатуры состояния (файлы, которые читают свидетели компонентов).
- `LICENSE` — MIT.

## Что изменилось в v0.1.2 (второй внешний аудит, 20.11)

- мутируемые литералы списков/словарей копируются при исполнении — состояние
  больше не течёт между вызовами и сделками («чистые функции» стали чистыми);
- <code>округлено</code> — Decimal от строкового представления (1.005 → 1.01,
  половина вверх без бинарной беды float);
- сравнение свидетелей: целые — точно (1e17+5 ≠ 1e17), дробные — допуск 1e-9
  (названный канон для денег);
- типы входов судятся на каждом кейсе (строка под объявленное число — красная);
- топливо: расчёт израсходовал 10 000 000 шагов тела — канон-отказ «топливо»
  (новое каноническое имя, v0.1.2), вместо вечного цикла;
- причина отказа доезжает в свод свидетеля;
- отказ компилятора пишется в reestr.jsonl — «что отвергнуто» фиксируется;
- NaN/Infinity запрещены при загрузке и сериализации (валидный JSON);
- кодоген: имя переменной — только идентификатор канона (инъекция кода закрыта,
  CWE-94).

## Что изменилось в v0.1.3 (третий раунд аудита, 21.11)

- ромб-импорт: цикл судится ПО ПУТИ (стек), повторный ввоз того же ХЕША
  дедуплицируется — композиция компонентов по хешу работает во всех ветках;
- ввоз привозит ВСЁ окружение ввозимого файла (транзитивные зовы не падали
  нет_договора — живая находка ромба);
- округлено: Decimal-контекст с запасом точности + DecimalException ловится
  сетью примитивника (огромные суммы — канон-отказ, не traceback);
- смешанное сравнение int↔float — точно (потеря точности больше не прячется);
- топливо в КОДОГЕНЕ: витки циклов считаются (1e9 → канон-отказ за ~2 с);
- tmp-файл записи полки уникален (гонка двух писцов закрыта);
- повторная компиляция того же хеша — лёгкая запись в реестр (без дубля AST);
- летопись — ХЕШ-ЦЕПОЧКА: каждая запись несёт хеш предыдущей («нельзя
  укоротить» становится проверяемым);
- арифметика «*» строга: строки умножать нельзя (склейка — примитивник);
- глубина рекурсии настраиваема: vm.ГЛУБИНА_ПОТОЛОК = N;
- опечатка тии_не_сошлись исправлена (типы).
  - дифференциальная проба: интерпретатор ↔ байткод сошлись 300/300 случайных
  выражений, расхождений 0.

## Что изменилось в v0.2.0 (четвёртый раунд — скорость, 21.11)

- кеш вердиктов свидетелей (`.deal_kesh/`): повторная компиляция
  неизменённых сделок не исполняет их заново — тяжёлый компонент
  7.23 с → 0.10 с (×70); сделки, касающиеся полки (в любом транзитивном
  зову), никогда не кешируются — их вердикт зависит от файлов полки;
- ключ кеша несёт хеш исходников ВМ — любое изменение семантики
  инвалидирует записи сама; запись атомарная (tmp + replace);
- `--parall`: свидетели сделок гонятся в ProcessPoolExecutor (обход GIL,
  падение одного свидетеля не роняет компилятор);
- мина краевых проб: проба наследовала счётчик топлива после свидетелей —
  вердикт зависел от порядка прогонов; теперь топливо сбрасывается на
  каждой пробе (дисциплина ВМ «расчёт случая сам за себя»);
- мина Python 3.14: каталог deal/ в sys.path затенял stdlib ast —
  цепочка concurrent.futures падала; каталог модуля из пути убран
  (пакет резолвится только через корень);
- проба v0.2.0: 12/12 ПАСС (кеш, параллел-эквивалентность,
  полочная изоляция, инвалидация), регрессия 8/8 компонентов —
  выводы байт-в-байт совпали с базой.

## Как запустить

Требуется Python 3.10+ (проверено на 3.14). Из папки пакета:

```bash
# скомпилировать и исполнить сделку с свидетелями:
python deal/kompilyator.py komponenty/cena_za_ednicu.deal
python deal/kompilyator.py komponenty/schetchik_podhodov.deal   # состояние на полке: 1→2
python deal/kompilyator.py komponenty/sud_ceny.deal             # оракул над компонентом
```

Компилятор печатает серийный хеш и вердикт по каждой сделке.
Каждый отказ — словами: стадия, виновник, причина, что править
(отказы приходят исключением Otkaz/DealOtkaz с этими полями; CLI v0.1.0
печатал сырой traceback — в v0.1.1 печатает отказ JSON-ом).

### Ускорение (v0.2.0)

```bash
python deal/kompilyator.py <файл.deal> --parall       # свидетели сделок в пуле процессов
python deal/kompilyator.py <файл.deal> --bez-kesh     # всегда полный прогон, кеш вон
```

- кеш вердиктов включён по умолчанию: сделки без полки в транзитивном
  замыкании зова не исполняются повторно — вердикт берётся из `.deal_kesh/`;
  смена ВМ или ввозов инвалидирует записи сама (хеш vm.py в ключе);
- `--parall` гонит свидетелей сделок в ProcessPoolExecutor (обход GIL,
  изоляция падения); краевые пробы пока серийные;
- проба пакета v0.2.0: тяжёлый компонент 7.23 с → 0.10 с на повторной
  компиляции (×70), вердикты байт-в-байт совпадают с полным прогоном,
  8/8 компонентов — регрессия чиста.

## Границы пилота (честно)

- зовы резолвятся внутри файла (ввозы по хешу между файлами — следующий шов);
- постусловие «даёт» печатается и исполняется на свидетелях, но не enforced статически;
- полка (файлы состояния) живёт только в папке `polka/` рядом с запуском.
