# DEAL — Часть 2: ЯЗЫК (канон-AST, проекция, декомпиляция, экспорт, синтаксис, превращения)

Мастер: [DEAL.md](DEAL.md). Все примеры — **КАНОН-КАНДИДАТ**: точная форма фиксируется
на ступени 1, смысл уже решён владельцем (таблица решений в мастере §4).

## §1. Хранение — канон-AST

Файл `.deal` хранит **машиночитаемый AST** в JSON — единственный источник компонента.
Никакого «текста программы» не существует: проекция (§2) — вычисляемый вид.

Форма узла (поля с русскими именами — язык дома):

```json
{"сделка": "<имя>",
 "входы":  [{"имя": "…", "тип": "число|строка|список|статус|файл"}],
 "выход":  "<тип>",
 "отказы": ["<каноническое_имя_отказа>"],
 "ввозы":  ["<хеш-адрес чужого договора>", "..."],
 "тело":   [{"оп": "…", "...": "..."}],
 "свидетель": [{"вход": {...}, "выход": ...}, {"вход": {...}, "отказ": "..."}],
 "вспомогательные": [ {"договор": "...", "тело": [...], "свидетель": [...]} ]}
```

Правила хранения, каждое от урока дома:

| Правило | Урок, от которого правило |
|---|---|
| Детерминированный порядок сериализации (имена полей и списки — фиксированный порядок) | мина перезаписи manifest.json с другим отступом; два серийных хеша одного смысла = мина |
| Одна кодировка utf-8, одно экранирование | cp1251 у heredoc, `lib/pechat_utf8.py` |
| Одно написание каждой конструкции (никаких алиасов) | `lib/postanovka.edinoobrazno`: 111 из 240 команд отвергались за форму |
| Ввоз — только хеш-адрес договора, пути запрещены | «выдуманный путь хуже пустого», застава существования `lib/postanovka.py` |
| Отказ — каноническое имя из списка договора, не строка | `lib/sintez_dsl.py`: крах формулы = `ERROR_INVALID_INPUT` по договору |

## §2. Проекция — читаемый вид

Проекция — **детерминированная печать AST** (как pretty-printer Roslyn/tree-sitter):
компилятор печатает её из AST по фиксированным правилам расстановки.

- **Биективность**: печать(AST) → проекция; разбор(проекция) → тот же AST. Два вида —
  одна истина, суд один (канон дома «один судья на одну истину»).
- Человек **читает и судит** проекцию; машина **ест** AST. Споры о синтаксисе и стиле
  исчезают: стиль — функция, не мнение.
- Проекция теряема без беды: печатается заново из AST за секунды.

## §3. ДЕКОМПИЛЯЦИЯ — всегда возможна, без потерь

Раздел по прямому вопросу владельца 14.11: «сможет ли другой ИИ декомпилировать наши файлы».

**Почему в DEAL декомпиляция — это не задача, а свойство.** Классическая декомпиляция —
реконструкция исходника из машинного кода: имена потеряны, типы потеряны, смысл угадывается.
В DEAL исходник — **AST**, а проекция — его печать. «Декомпилировать» = напечатать. Всегда,
без потерь, за секунды.

| | Декомпиляция машинного кода | «Декомпиляция» DEAL |
|---|---|---|
| Что восстанавливается | приблизительный код | точный AST |
| Имена и типы | потеряны/угаданы | в AST всегда |
| Намерение (договор, свидетели) | потеряно | в файле всегда |
| История изменений | недоступна | летопись (превращения were/стало) |
| Скорость | часы-дни, результат неполон | мгновенно, результат полон |
| Проверка верности | нельзя | сверка хеша: печать(разбор(проекция)) == AST |

**Восстановление при беде** (каждая строка — прецедент дома):

- Потерялась проекция → печатается из AST.
- Потерялся AST, есть проекция → разбор проекции (биективность, §2).
- Потерялся файл целиком → летопись превращений + полка: каждое превращение было→стало,
  историю нельзя укорачивать — прецедент `lib/rd_zadachi._zapis_letopisi` + `lib/detect_rollback`.
- Натив-бинарь (ступень 4) сам по себе не декомпилируется — но это **перевозка, а не хранение**:
  AST компонента всегда лежит в полке дома; при подъёме бинаря сверяется хеш договора
  (прецедент манифеста sha256 в Рой-жидкости).

## §3.5. Прозрачность и режимы экспорта

По вопросу владельца: «сможет ли другой ИИ быстро декомпилировать наши файлы при получении?»

**Прямой ответ: да, мгновенно и полностью.** Это осознанное свойство, и оно не хуже статуса
кво: питон-дом уже возит читаемые .py по полке — получивший .py тоже понимает всё мгновенно.
DEAL даёт получившему даже больше (договор = намерение, свидетели = доказанное поведение,
летопись = история).

Где реальная защита дома — она не в формате файла:

| Защита | Прецедент в доме |
|---|---|
| Доступ к полке: закрытая папка хостинга + FTP-креденциалы | `data/ftp.json`, полка `data/roy` на debug.lteam.ru |
| Фильтр секретов при вывозе через каналы | `lib/qwen_oblako_filtr.py` |
| Никаких секретов в теле компонента (только полка-адреса) | правило языка §6 |

**Режимы экспорта — то, чего у питона нет.** Режим выбирается ПО КОМПОНЕНТУ:

| Режим | Наружу идёт | Понимание чужого ИИ | Кому предназначен |
|---|---|---|---|
| Прозрачный .deal | AST + проекция + свидетели + летопись | полное, мгновенное | свои узлы, приёмка, перенос, сотрудники-облака |
| Натив (ступень 4) | машинный код без AST | как раздача бинарника — трудно и неполно | компоненты, которые хочется скрыть |

AST при любом режиме остаётся в полке дома. Питон такого выбора не имеет вовсе.

## §4. Синтаксис проекции — полный

Ключевые слова проекции — русские (язык дома). Полный список: `договор`, `требует`,
`даёт`, `отказ`, `сделка`, `тело`, `свидетель`, `верни`, `если`, `иначе`, `для-каждого-до`,
`стой`, `пусть`. Латинские идентификаторы имён (канон `edinoobrazno`: в шелле латиница).

### Типы

`число`, `строка`, `список[<тип>]`, `статус` (канонические статусы), `файл` (адрес на полке),
`хеш`. Составных структур нет нарочно — сложное собирается сделками (тело и witnesses вместо
классов; урок: дом живёт плоскими JSON-полями).

### Договор

```
договор деление(а: число, б: число) -> число
  требует  б != 0
  даёт     округлено(а / б, 2)
  отказ    деление_на_ноль
```

- `требует` — предусловие (несоблюдение = канонический отказ `нарушен_договор`, не падение;
  урок «функция не возвращает правдоподобную пустоту»).
- `даёт` — постусловие: проверяется на каждом свидетель-кейсе автоматически.
- `отказ` — закрытый список канонических имён отказов (урок `lib/sintez_dsl.py`).

### Сделка — единица программы

```
сделка цена_за_единицу(месячный: число, человек: число) -> число
  тело:
    цена  = деление(месячный, человек)
    верни цена
  свидетель:
    месячный=100000, человек=4 -> 25000.00
    месячный=100000, человек=0 -> отказ деление_на_ноль
```

- Сделка = заголовок-договор + тело + свидетель. **Всё есть сделка**: вспомогательные
  функции — тоже сделки со своими свидетелями; чистый договор без тела = интерфейс.
- Тело — ограниченный набор операций (§4.1); свидетель — закрытые кейсы (§4.2).

### §4.1 Операции тела

| Оп | Пример проекции | Суд компилятора |
|---|---|---|
| присваивание | `цена = деление(м, ч)` | правая часть сходится по типам |
| зов | `деление(м, ч)` | договор по хешу существует, требует/отказы учтены |
| поле | `месячный` | имя объявлено во входах/пусть |
| константа | `25000.00`, `"текст"` | литерал |
| если/иначе | `если ч <= 0: ... иначе: ...` | обе ветви покрыты свидетелями |
| для-каждого-до | `для-каждого-до(строк, n)` — цикл ТОЛЬКО с границей-в-договоре | неограниченный цикл невозможен (урок JPL: правило 4) |
| стой | `стой отказ деление_на_ноль` | отказ назван в договоре сделки |
| верни | `верни цена` | тип сходится, постусловие `даёт` выполнимо |
| пусть | `пусть предел = 5` | константа тела, не мутируется |

Нет: указателей, eval-подобных, свободных функций, побочных эффектов в теле (§6).

### §4.2 Свидетель — доказательство сделки

```json
{"свидетель": [
  {"вход": {"месячный": 100000, "человек": 4},  "выход": 25000.00},
  {"вход": {"месячный": 100000, "человек": 0},  "отказ": "деление_на_ноль"}
]}
```

Правила суда (уроки `tools/zadachi.py` — заданник дома):

1. Минимум **3 показанных кейса + 3 скрытых** (скрытые судят, показанные ведут перебор).
2. **Края обязательны**: пустой вход, один элемент, все равные, ноль, максимум —
   в обеих половинах («иначе подгонка неизбежна для любого перебора» — шапка заданника).
3. Подгонка считается числом: кейсы, отвергнутые скрытым кейсом, называют в отказе
   (прецедент `lib/sintez_dsl.py` — «подгонки_отвергнуто»).
4. Постусловие `даёт` договора проверяется на КАЖДОМ кейсе автоматически.

### §4.3 Состояние — только полка

Компонент без состояния — чистая функция (судится в пустоте, как оракулы). Компонент с
состоянием читает/пишет **файлы полки** по канону дома: атомарная запись tmp+replace+fsync
(`lib/zapis_atomnyi`), O_EXCL-замки (прецедент `most_nasos.zayavka`), манифест с sha256
(Рой-жидкость). Состояние в куче процесса запрещено: сделка без побочных эффектов за
границей полки.

## §5. Шестнадцать атомарных превращений — весь способ работы ИИ

ИИ не редактирует AST руками: ИИ подаёт превращения из закрытого набора. Каждое — атомарно
(либо полностью принято, либо отвергнуто словами), судится компилятором, попадает в летопись.

| # | Превращение | Предусловие | Суд компилятора |
|---|---|---|---|
| 1 | ввести-сделку | имя свободно, договор полон | ≥1 кейс свидетеля, края |
| 2 | ввести-договор (вспомогательный) | имя свободно | договор полон, отвергнутых зовов нет |
| 3 | заменить-тело | типы сходятся, отказы учтены | все свидетели исполнены, `даёт` на каждом |
| 4 | добавить-кейс-свидетель | кейс не дубль | исполняется сейчас; суд краёв: недостающий край — претензия |
| 5 | убрать-кейс | остаются ≥3+3 с краями | исполняется, скрытые не расшатаны |
| 6 | сузить-требует | новый предусловие сильнее | все зовущие проверены заново |
| 7 | расширить-даёт | новое постусловие сильнее | все свидетели перегнаны |
| 8 | добавить-отказ | имя канонично, не дублирует | тела зовущих называют новый отказ |
| 9 | заменить-зов | новый договор по хешу | типы, требует, отказы учтены |
| 10 | переименовать-с-переносом-зовущих | новое имя свободно | все зовущие перенесены, ни один не потерян |
| 11 | расколоть-по-шву | шов назван (два блока тела) | две сделки в сумме эквивалентны: свидетели перегнаны |
| 12 | влить-сделки | узы: одна зовёт только другую | слитая эквивалентна сумме |
| 13 | ввести-тип | имя свободно | применение типу только через сужение/расширение |
| 14 | пометить-карантин | тело непроверяемо формально | код живёт ТОЛЬКО в песочнице (прецедент `sandbox.py`), на границе не имеет права |
| 15 | вынести-в-примитивник | оп поддерживается ВМ (§3 примитивника, part 3) | тело становится вызовом ВМ, свидетели перегнаны |
| 16 | удвоить-компонент-с-вариацией | имя свободно | новый компонент независим (для перебора — урок `lib/sintez_dsl.py`) |

Превращения 6/7/8/9/10 — «договорные»: они меняют договор, поэтому компилятор обязан
перегнать всех зовущих и перегнать все свидетели — цена изменения договора честно
высока, цена изменения тела (3) дёшево.

## §6. Запреты языка

1. Свободный текст в теле (только операции §4.1 из закрытого набора).
2. Побочные эффекты за границей полки (сеть, процессы, экран — только карантинный ярус §5.14).
3. Неограниченные циклы (граница — часть договора).
4. Вольные зависимости по путям/именам (только хеш-адреса договоров).
5. Мутабельное глобальное состояние (только полка, канон атомарной записи).
6. Два написания одной конструкции (канон enforced компилятором).
7. Секреты в теле компонента (только адреса полки; секреты живут вне — фильтр
   `lib/qwen_oblako_filtr.py` отсекает при вывозе).

## §7. Пять полных примеров

### Пример 1 — деление с копейками (реальная задача синтеза Б5)

См. мастер §3 (полный) и часть 3 §4 (свидетель-суд). Показывает: договор с `требует`,
канонический отказ, края в свидетеле.

### Пример 2 — компонент с состоянием на полке (перенос `pulse/fon_razlozhit.py`)

```
договор счётчик_подходов(полка: файл) -> число
  требует  файл на полке
  даёт     число >= 0
  отказ    полка_не_доступна

сделка считай(полка: файл) -> число
  тело:
    было = полка.читай(полка)                    # примитивник ВМ: чтение файла-JSON
    было  = если было == пусто: 0 иначе: было.число
    стало = было + 1
    полка.пиши(полка, стало)                     # атомарная запись — примитивник ВМ
    верни стало
  свидетель:
    полка с {"число": 4}      -> 5
    пустая полка              -> 1
    полка с мусором           -> отказ полка_не_доступна
```

Показывает: состояние только через полку, примитивники ВМ (`.читай`/`.пиши` — атомарная
запись внутри ВМ, ИИ её не пишет), края.

### Пример 3 — DEAL-оракул (аналог `RnD/oraculy/ORAKUL.py`)

Оракул в DEAL — сделка с договором «истинным без проекта»: тело зовёт ТОЛЬКО проверяемую
сделку, свидетель — решённые кейсы. Компонент экспортируется, решение грузится из полки
(аналог argv[1]), код возврата решает. Суд оракула — та же машина, что суд кладки.

### Пример 4 — компонент-служба (перенос `pulse/fon_razlozhit_sluzhba.py`)

Служба дома = сделка `дежурь()` с циклом-с-границей (`для-каждого-до(тактов, предел)`)
и состоянием на полке (пульс-файл, статус-файл). Рецепт+строка таблицы+галочка
автостарта — **не часть языка**: это данные дома, которые DEAL-ломтик несёт рядом
(карта файлов — часть 4 §1). Урок дня встроен: панельная видимость — в таблице дома,
не в языке.

### Пример 5 — кладка end-to-end: лог превращений

```
слайс (2.5к токенов): договор цели + набор превращений + 3 примера
превращение 1  ввести-сделку      → принята (край есть)
превращение 2  добавить-кейс      → ОТКАЗ: «кейс дубль кейса 1; ожидается край
                                    „все равные“ — смотри суд краёв» (виновник+причина+что править)
превращение 2' добавить-кейс (край) → принята
превращение 3  заменить-тело      → ОТКАЗ: «зов деление_не_то: договора нет в ввозах;
                                    доступен деление (хеш a1b2…)»
превращение 3' заменить-тело      → принята: 6/6 кейсов сошлись, даёт проверено
итог: компонент с хешем, летопись из 5 записей, проекция напечатана
```

Оба отказа названы словами, оба исправлены ИИ без человека — это и есть петля, которую
DEAL делает дешёвой (часть 3 §5).
