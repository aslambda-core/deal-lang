# DEAL — Часть 3: КОМПИЛЯТОР (8 стадий, отказы словами, суд свидетельств, bootstrap, токены)

Мастер: [DEAL.md](DEAL.md). Язык: [DEAL_YAZYK.md](DEAL_YAZYK.md). Всё ниже — ПРОЕКТ
(ничего не построено); числа помечены ПРОЕКТ-МЕРКА.

## §1. Конвейер — восемь именованных стадий

```
 превращение ИИ (атомарная операция над AST, язык §5 части 2)
     │
     ▼
[1] ПРИМ        — форма: операция из закрытого набора, AST разобран, поля полны
[2] СУД ПОЛНОСТИ — договор сделки полон: входы/выход/отказы/ввозы, имена каноничны
[3] СУД ВЫПОЛНИМОСТИ — типы сходятся статически: зовы по хешам существуют,
                       требует/отказы зовущих учтены, границы циклов названы
[4] ИСПОЛНЕНИЕ СВИДЕТЕЛЕЙ — ВМ гонит показанные и скрытые кейсы в песочнице;
                       постусловие «даёт» на каждом; подгонка считается числом
[5] СЕРИЙНЫЙ ХЕШ — детерминированная сериализация AST → sha256 (адрес компонента)
[6] ЛЕТОПИСЬ    — превращение записано было→стало (историю нельзя укоротить,
                       прецедент lib/rd_zadachi._zapis_letopisi + lib/detect_rollback)
[7] РЕЕСТР      — хеш → запись: кто подал, когда, какие свидетели, что отвергнуто
[8] ВЫДАЧА      — компонент + проекция (печать AST) + протокол судов
     │
     ▼
 принят: компонент жив в реестре   |   отвергнуто: ОТКАЗ словами на стадии k
```

Каждая стадия — отдельная функция, судится в пустоте без ВМ и сети (урок
`lib/rd_pretenzii.py`: «здесь нет ни часов, ни диска — претензии проверяются на выдуманных
карточках»). Стадии 1–3 чистые; 4 — единственная с побочным исполнением, идёт в песочнице
(прецедент `sandbox.py`: docker/process, отказ в безопасную сторону, понижение изоляции
только именованное).

## §2. Отказ — всегда словами (канон Otkaz дома)

Формат отказа компилятора: `{стадия, виновник, причина, что_править}`. ИИ исправляет
по словам, без человека. Четыре живых примера формата (претенденты на реальный журнал):

```
{"стадия": 3, "виновник": "зов деление_не_то", 
 "причина": "договора нет в ввозах сделки; доступен деление (хеш a1b2c3)",
 "что_править": "замени зов на деление или добавь ввоз хеша"}

{"стадия": 4, "виновник": "кейс 2 свидетеля цены_за_единицу",
 "причина": "ожидали 25000.0, ВМ выдала 25000.0000001 — даёт не выполнено",
 "что_править": "округляй через округлено(x, 2) или правь тело"}

{"стадия": 2, "виновник": "сделка считай",
 "причина": "отказ полка_не_доступна назван в свидетеле, но не в списке отказов договора",
 "что_править": "добавь отказ в договор или убери кейс"}

{"стадия": 3, "виновник": "тело считай, для-каждого-до",
 "причина": "граница цикла не названа в договоре (неограниченный цикл запрещён)",
 "что_править": "объяви предел во входах или в пусть"}
```

Каждое поле — по уроку дома: «отказ не бывает молчаливым», «назван виновник и причина».
Метрика успеха (рубильник мастера): ≥90% кладок исправлены ИИ по словам отказа.

## §3. Суд свидетельств — алгоритм

Прямой наследник двух проверенных машин дома: заданника (`tools/zadachi.py`,
`data/zadachi/prinyatye.json`) и DSL-синтеза (`lib/sintez_dsl.py`).

1. **Показанные кейсы ведут**: сделка обязана сходиться на всех показанных.
2. **Скрытые кейсы судят**: верификатор гонит свои — подгонка под показанные
   отбрасывается скрытым кейсом, счётчик «подгонки_отвергнуто» растёт, число
   называется в отказе.
3. **Края обязательны**: пустой вход, один элемент, все равные, ноль, максимум — в обеих
   половинах (шапка заданника: «иначе подгонка неизбежна для любого перебора»).
4. **Постусловие «даёт»** проверяется на каждом кейсе автоматически (дважды: телом и
   постусловием — несовпадение = отказ договора).
5. **Статистика честности**: доля кейсов, поимённо названных при создании (не автосгенерённых
   краями) — прибор качества свидетеля; «проверка, которая только предупреждает, — не
   проверка» (канон атласа).

## §4. Bootstrap-лестница — кто несёт язык (решение владельца: питон→сам себя→натив)

Язык DEAL и его байткод — свои целиком. Чужой код появляется ОДИН РАЗ — как дровосек
первой ВМ — и уходит, когда DEAL сам себя компилирует.

### Ступень 1 — питон-ВМ (дровосек)

- Интерпретатор AST: исполняет тело-сделки против свидетелей. Оценка объёма: ~1500–2500
  строк питона, разрезанные по частям ≤600 (храповик дома `tools/razmer.py`).
- Примитивник — **замороженный набор инструкций ВМ** (ИИ его не пишет никогда):
  `числа(+−×÷, округлено, копейки) · строки(регистр, края, слова, числа-текста, склейка) ·
  списки(длина, сумма, максимум, минимум, среднее, сортировка, уникальные, разворот) ·
  файлы полки(читай, пиши-атомарно, есть) · хеш · время · статус`.
  Набор унаследован от живых таблиц `lib/sintez_dsl.py` (OPS) и полки дома —
  **перечислен целиком при ступени 1 и дальше растёт только решением владельца**.
- Компилятор стадий 1–3, 5–8 — тоже питон, ~1000 строк. Стадия 4 зовёт ВМ.
- Все части судятся штатными пробами дома (`tests/pyt_vyzov.py`), питон-код стережёт
  храповик 600 — это «костыли обучения», живущие до конца миграции.

### Ступень 2 — сам себя (self-hosting)

- Компилятор (8 стадий) переписывается НА DEAL. Проверка одна и честная: по **золотому
  корпусу превращений** (снимок всех превращений ступени 1) питон-компилятор и DEAL-компилятор
  обязаны дать байт-в-байт одинаковый реестр. Расхождение хоть в бите — самокомпиляция не принята.
- После принятия питон-дровосек уходит в карантин `_to_delete/` (дом ничего не удаляет).

### Ступень 3 — свой байткод

- DEAL-превращение тела → байткод собственной стековой ВМ (стековая выбрана: проще
  верифицировать свидетелями — трасса стека судима).
- Байткод — тоже AST-подобные данные (JSON), летопись и хеши работают так же.

### Ступень 4 — натив

- Кодогенерация горячего подмножества в машинный код x86-64: судьи, оракулы, поиск.
- Свой бэкенд, без LLVM/Rust как цели (решение владельца). Натив — **перевозка**:
  AST всегда живёт в полке (часть 2 §3).
- Примитивник ступени 4 = те же замороженные инструкции, реализованные кодогенерацией.

## §5. Токен-экономика — почему горизонт дешевле стерта

Главный жегатель токенов в агентном кодинге — **петля чинения**, не написание. Живые
случаи одного дня 13.11:

| Случай | Петля (питон) | Токены (ПРОЕКТ-МЕРКА по счётчикам дня) |
|---|---|---|
| NameError: `import time` забыт в recepty | редактирование → проба → exec живого исходника → ловля | ~15к на погоню |
| Вырезка по маркерам съела RECIPES | правка → синтаксис → cat-file восстановление | ~20к |
| Два index.lock соседей | ожидания, повторы, ручной разбор | ~10к |
| Чтение файла 600 строк ради точки правки | чтение целиком | ~8к только чтение |
| Фон-кладка: LFM съела бюджет рассуждениями (10/10 пустых) | переспросы ×2 | сотни к |

DEAL-правка того же класса:

| Шаг | Токены (ПРОЕКТ-МЕРКА) |
|---|---|
| Слайс договора (компилятор сам отдаёт только нужный договор + 3 примера) | 1–2к |
| Превращение (атомарная операция над AST) | 0,3–0,5к |
| Отказ компилятора словами + исправленное превращение | 2–5к за цикл |
| Чтение: проекция нужной сделки (не файла целиком) | 0,5–1к |

Разница не в скорости первого захода (старт дороже: ×2–5 на компонент в первые недели —
честно названо), а в **петле**: ошибка ловится на первом касании словами компилятора,
а не через час на чужой строке. Дом уже измеряет «потрачено-токены» на каждой карточке —
рубильник считается без новых приборов.

## §6. Что компилятор НЕ делает (границы, по канону шапок)

- Не зовёт никакую LLM — верификация детерминирована (судья-модель d1 подключается
  ВНЕ компилятора, для вероятностных судов кладки, часть 4).
- Не понижает изоляцию молча (прецедент `sandbox.py`: отказ в безопасную сторону).
- Не пишет в живой дом напрямую: принятый компонент попадает в реестр, перенос в тело
  дома — теми же дверями, что сегодня (доводчик, приёмка владельца).
- Не судит «зачем» — договор судим машиной, смысл решает владелец/конвейер.
